## Overview

Text style utilities are role-based typography classes.

Examples:

```text
display-l
heading-h1
heading-h2
body-l
body-m
label-m
caption-m
button-m
```

They are generated as Tailwind `@utility` classes.

```html
<h1 class="display-l">Main headline</h1>
<p class="body-l">Lead paragraph</p>
```

## What They Include

A text style can include:

- font family
- font size token
- line height
- letter spacing
- font weight
- font style
- text transform

Example output shape:

```postcss
@utility display-l {
  font-family: var(--font-sans);
  font-size: var(--text-7xl);
  line-height: 0.95;
  letter-spacing: 0;
  font-weight: 700;
  font-style: normal;
  text-transform: none;
}
```

## Why Use Text Styles

**Text tokens** describe size.

**Text styles** describe purpose.

Less ideal:

```html
<h1 class="text-7xl font-bold leading-none">
  Headline
</h1>
```

Better:

```html
<h1 class="display-l">
  Headline
</h1>
```

`display-l` carries design intent. It also stays synced with Figma text styles.

## Usage

```html
<section class="container-grid py-section-xl">
  <p class="label-m mb-md">New Release</p>

  <h1 class="display-l">
    A complete fluid design system.
  </h1>

  <p class="body-l mt-lg w-col-6">
    Text styles keep typography consistent across design and code.
  </p>
</section>
```

## `vw` font-size behavior

Text styles use generated typography tokens by default, usually `clamp(...)`. That means text grows between configured min and max viewport widths, then stays capped.

Add the `vw` modifier when a text variable should use its viewport-scaled font-size value:

```html
<h1 class="display-l vw">Scales wider on large screens.</h1>
```

A `vw` modifier on an ancestor enables viewport-scaled font sizes for descendant text variables:

```html
<section class="container-grid vw">
  <h1 class="display-l">Scales wider on large screens.</h1>
</section>
```

Use `!vw` on the text variable itself to opt out of inherited or direct `vw` scaling:

```html
<section class="container-grid vw">
  <h1 class="display-l !vw">Stays capped on large screens.</h1>
</section>
```

`!vw` wins over `vw`, but it is local only. It does not block `vw` scaling for a subtree when placed on a parent.

The generated CSS uses explicit selectors so local `!vw` beats both inherited and direct `vw`:

```postcss
.vw .display-l,
.display-l.vw {
  font-size: [viewport-scaled font-size value];
}

.vw .display-l.\!vw,
.display-l.vw.\!vw,
.display-l.\!vw {
  font-size: [default font-size value];
}
```

The generated CSS no longer exports separate `*-vw` text utility classes or `*-no-vw` helpers.

## Best Practice

Use **text styles** for real content.

Use raw `text-*` classes only for exceptions or one-off technical cases.

Use modifiers after the base text utility in examples:

```html
<h1 class="display-l vw">Fluid display text.</h1>
<h1 class="display-l !vw">Fixed display text.</h1>
```
