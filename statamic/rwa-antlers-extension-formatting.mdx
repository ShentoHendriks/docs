---
title: "Formatting"
description: "Format mixed Antlers, HTML, attributes, Tailwind classes, partial blocks, and nested content."
---

RWA Antlers Support registers itself as the default formatter for `.antlers.html` files.

It formats Antlers and nested HTML without requiring `prettier-plugin-antlers`.

## Format command

Use the normal VS Code format commands:

- **Format Document**
- **Format Selection**
- Format on save when enabled

The extension contributes this default:

```json
{
  "[antlers]": {
    "editor.defaultFormatter": "local.rwa-antlers-support"
  }
}
```

## Antlers and HTML indentation

The formatter keeps nested HTML and Antlers blocks readable.

```html
<section>
  {{ collection:blog }}
    <article>
      <h2>{{ title }}</h2>
    </article>
  {{ /collection:blog }}
</section>
```

It bases indentation on element and Antlers nesting rather than on incidental attribute line breaks.

## Partial blocks

Explicit paired partial blocks are formatted like normal nested blocks.

```html
{{ partial:eyebrow }}
  Contact us
{{ /partial:eyebrow }}
```

Standalone partial tags stay standalone.

## HTML child complexity

The formatter decides whether HTML should stay inline or expand based on child content and complexity.

Short labels can stay inline:

```html
<a href="{{ url }}">{{ title }}</a>
```

Prose, nested children, or mixed blocks expand to multiline markup:

```html
<article>
  <h2>{{ title }}</h2>
  <p>{{ excerpt }}</p>
</article>
```

## Long attributes

Long attributes can split across grouped attribute lines.

This is especially useful for long Tailwind `class` values.

```html
<section
  class="container-grid gap-section py-section"
  data-theme="dark"
>
  {{ content }}
</section>
```

The formatter also collapses multiline opening tags before indentation so attributes and the closing `>` stay attached to the tag instead of leaving `>` alone on its own line.

## Antlers strings in HTML attributes

When double-quoted Antlers string literals appear inside double-quoted HTML attributes, formatting normalizes the inner Antlers quotes to single quotes.

```html
<meta content="{{ title ?? 'Untitled' }}">
```

This prevents broken attributes like:

```html
<meta content="{{ title ?? "Untitled" }}">
```

The formatter preserves the closing `}}` while making the HTML attribute valid.

## Inline and collapsed markup cleanup

The formatter can expand collapsed or glued markup into readable blocks.

It handles:

- Split inline HTML pairs before indentation
- Stacked opening tags such as `<div><a><img ...>`
- Parent closing tags after void elements such as `<img ...></a>`
- Adjacent siblings such as `</h1><p>`
- Leading Antlers opening tags before inline HTML
- Inline Antlers block pairs inside HTML elements

For example:

```html
<span>{{ made_by }} {{ label }} {{ /made_by }}</span>
```

can become:

```html
<span>
  {{ made_by }}
    {{ label }}
  {{ /made_by }}
</span>
```

## Scalar values stay stable

Scalar Antlers variables stay inline when they sit directly before an HTML closing tag.

```html
<div>{{ ingredient }}</div>
```

This avoids format-on-save churn.

## Blank line cleanup

Whitespace-only lines are removed during formatting, including blank lines left between closing HTML or Antlers tags.

## Line breaks inside text

Nested HTML indentation stays stable when inline line breaks appear inside text content.

The formatter also normalizes `<br>` and invalid `</br>` tags to:

```html
<br />
```

## Tailwind class sorting

Static Tailwind classes in HTML `class` attributes are sorted during formatting.

The sorter follows Tailwind-style ordering principles:

- Custom classes first
- Plain utilities before modifiers
- Responsive variants last
- Layout-related utilities before decorative utilities where possible

It keeps useful relationships stable, such as:

- Flex alignment before gap spacing
- Aspect ratio before background color
- Margin before layout sizing
- Radius before border width
- Axis padding before side-specific padding
- Semantic typography utilities in Tailwind-style order

## Tailwind v4 theme awareness

The formatter scans project CSS for Tailwind v4 declarations.

It understands:

- `@theme` variables
- `@utility` declarations
- Custom spacing tokens
- Custom color tokens
- Custom radius tokens
- Custom shadow tokens
- Custom breakpoints
- Wildcard utilities such as `w-col-*`, `ml-col-*`, and `gap-col-*`

This lets custom utilities sort with the right utility group instead of being treated as random strings.

## Dynamic class attributes

Dynamic class attributes are kept unsorted.

When a class value depends on Antlers expressions or complex runtime conditions, the formatter avoids rearranging it in a way that could change meaning.

## What formatting does not do

The formatter does not normalize Antlers comments or PHP blocks.

Use this for template structure, HTML, Antlers blocks, attributes, and static Tailwind class values. Keep application logic readable before formatting.
