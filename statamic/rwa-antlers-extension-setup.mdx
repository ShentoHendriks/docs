---
title: "Setup and workspace index"
description: "How the extension discovers Statamic project structure and keeps suggestions current."
---

The extension works best when VS Code is opened at the root of a Statamic project.

It registers `.antlers.html` files as the `antlers` language, adds the Statamic file icon, sets itself as the default formatter for Antlers files, and starts a workspace index for project-aware suggestions.

## What the index reads

The workspace index scans common Statamic paths and caches the result in memory.

The index includes:

- Collection handles from `content/collections/*.yaml` and `*.yml`
- Collection entries and selected `template:` or `blueprint:` front matter
- Navigation handles from `content/navigation`
- Global set handles from `content/globals`
- Taxonomy handles from `content/taxonomies`
- Blueprint fields from `resources/blueprints/**/*.yaml` and `*.yml`
- Form handles from `resources/forms/*.yaml` and `*.yml`
- Form blueprint fields from `resources/blueprints/forms/*.yaml` and `*.yml`
- Imported fieldsets from `resources/fieldsets`
- Partial handles from `resources/views/partials/**/*.antlers.html`
- Partial paths used by Bard and Replicator set examples

## Refresh behavior

The index refreshes before building completions and also reacts to relevant file changes.

This means completion details can update after you:

- Rename or move a partial file
- Add a blueprint field
- Change a Replicator set
- Add a collection or taxonomy
- Add entries that select a different template
- Save a form or form blueprint from the Statamic Control Panel

The extension uses cached index data rather than scanning the project from scratch for every keystroke.

Manual form helper partials refresh from the current form blueprint when files under `resources/forms/` or `resources/blueprints/forms/` are created or changed. That keeps generated width styles and required markers synced with Control Panel form settings.

## Language server

The optional Antlers language server provides diagnostics for delimiter problems, tag-pair mismatches, missing closing tags, style advice, and filename conventions.

The language server starts independently from the rest of the extension. If it fails, syntax highlighting, formatting, tag pairing, and extension-side IntelliSense can still keep working.

You can disable it with:

```json
{
  "antlers.languageServer.enabled": false
}
```

## Default editor behavior

For Antlers files, the extension contributes these defaults:

- RWA Antlers Support is the default formatter
- Word-based suggestions are disabled
- Snippet suggestions appear near the bottom
- Quick suggestions are enabled inside strings
- Emmet treats Antlers as HTML
- Tailwind CSS treats Antlers as HTML

That gives you HTML, Tailwind, and Statamic suggestions in the same file without making plain word suggestions dominate the list.

## Supported file type

Only files matching `.antlers.html` are registered as Antlers files.

If a template is named `example.html`, VS Code treats it as HTML and the extension will not provide the full Antlers experience.

The diagnostics page documents the filename advice the extension gives for view conventions.
