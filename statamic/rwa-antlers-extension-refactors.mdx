---
title: "Partials and refactors"
description: "Extract partials, create fields, create Replicator sets, switch blueprints, and keep references synced."
---

The extension includes refactor workflows for common Statamic template work.

These features are designed for Antlers files inside a normal Statamic project with `resources/views` and `resources/blueprints` available.

## Partial navigation

Partial handles are indexed from:

```text
resources/views/partials/**/*.antlers.html
```

You can command-click or ctrl-click supported partial references to open the matching partial file.

Supported references include:

```html
{{ partial:cards.article }}
{{ partial src="cards.article" }}
```

Partial suggestions hide leading underscores per path segment.

A file at:

```text
resources/views/partials/cards/_article.antlers.html
```

is referenced as:

```html
{{ partial:cards.article }}
```

## Rename and move sync

When you rename or move partial files inside VS Code, the extension updates exact partial references across `resources/views/**/*.html`.

It supports:

- Shorthand tags such as `{{ partial:eyebrow }}`
- Paired closing tags such as `{{ /partial:eyebrow }}`
- `src` attributes such as `{{ partial src="eyebrow" }}`

Dot and slash path styles are preserved where possible.

## Extract to partial

Use **Antlers: Extract to Partial** on a non-empty selection in an Antlers file.

The command:

1. Opens a folder picker rooted at `resources/views/partials`
2. Creates the `partials` folder if needed
3. Lets you choose or create a folder
4. Prompts for a partial name
5. Creates the partial file
6. Replaces the selection with a partial tag

## Extract folder picker

The folder picker is designed for nested partial-heavy projects.

It shows:

- The current folder
- Child folders
- Search results anywhere under `partials`

Use:

- Enter to select the current folder or highlighted search result
- `Ctrl+N` on Windows/Linux or `Command+N` on macOS to create a folder
- Esc to clear search or go up one level
- Click outside the picker to close it

When you create a folder, the picker opens that new folder so you can keep drilling down.

## Partial name normalization

Extracted partial names are normalized to Statamic partial filenames.

| Input | File |
| --- | --- |
| `eyebrow` | `_eyebrow.antlers.html` |
| `Hero Section` | `_hero_section.antlers.html` |
| `_hero-section.antlers.html` | `_hero_section.antlers.html` |
| `heroSection` | `_hero_section.antlers.html` |

The inserted handle removes leading underscores per path segment.

```html
{{ partial:eyebrow }}
```

## Extract to partial edge cases

Extract to partial:

- Only appears for non-empty selections
- Only appears in Antlers files
- Requires `resources/views` in the current workspace
- Refuses to overwrite existing partial files
- Returns to the previously selected folder when Esc is pressed from the partial name input

## Create Replicator set

Use **Antlers: Create Replicator Set** on selected Antlers or HTML.

The command:

1. Resolves relevant blueprints for the current collection
2. Asks which blueprint should receive the set
3. Asks for a set name
4. Creates `resources/views/partials/sets/{blueprint}/_{set}.antlers.html`
5. Moves the selected code into that partial
6. Replaces the original selection with a dynamic Replicator render loop
7. Inserts the set into the selected blueprint Replicator

Example replacement:

```html
{{ page_builder }}
  {{ partial src="sets.pages.{type}" }}
{{ /page_builder }}
```

## Replicator render loop dedupe

Create Replicator Set only inserts the dynamic render loop once per template and Replicator path.

If the same loop already exists, creating another set still creates the set partial and blueprint set, but removes the selected static code instead of duplicating the loop.

## Relevant blueprint choices

Create Replicator Set shows existing relevant blueprint choices formatted like:

- `Home (Pages)`
- `Page (Pages)`
- `Project (Pages)`

If the selected blueprint has no Replicator field, the command automatically adds a standard `sections` Replicator before creating the set.

Blueprint creation choices live in **Set Blueprint**, not in Create Replicator Set.

## Page-specific set paths

Page-specific blueprints store sets under nested partial roots.

For a page blueprint like:

```text
resources/blueprints/collections/pages/home.yaml
```

set partials are stored under:

```text
resources/views/partials/sets/pages/home/_hero_section.antlers.html
```

and rendered with:

```html
{{ partial src="sets.pages.home.{type}" }}
```

## Set Blueprint

Use **Antlers: Set Blueprint** when no text is selected.

The command finds the current page entry from the template, shows blueprint choices, and updates the entry's `blueprint:` front matter.

It can switch between:

- The collection default blueprint
- Existing page-specific blueprints
- A newly created page-specific blueprint

If the page-specific blueprint does not exist, the picker can show an option like:

```text
+ Create page-specific blueprint Home (Pages)
```

Choosing it creates the blueprint file with `Home` prefilled as the editable name, then assigns the page to `blueprint: home`.

The current selected blueprint is always placed at the top of the picker.

## Create Field

Use **Antlers: Create Field** on selected text in normal Antlers templates.

The command:

1. Resolves the current page or collection blueprint
2. Asks for field type and display name
3. Replaces the selected text with `{{ field_handle }}`
4. Writes the field into the selected blueprint
5. Clears Statamic's Stache cache

Create Field does not appear inside `resources/views/partials/**`, including Replicator set partials.

## Field placement

Create Field places the new field near the selected template position by reading nearby direct blueprint variables.

Examples:

- A selection between `{{ title }}` and `{{ description }}` inserts between those fields
- A selection below `{{ sections }}` inserts below `sections`
- A selection above another field inserts before it
- New fields are never inserted above `title`

Duplicate handles are blocked against direct fields in the target blueprint. Nested Grid or Replicator-set children do not block the same handle.

## Default values

Text and Textarea fields ask whether the selected text should become the field's default value.

Multiline defaults are written as YAML block values.

When Create Field targets a page-specific blueprint and you choose that default-value option, the selected text is also seeded into the current entry data. Collection-default blueprints are not auto-filled.

## Create Replicator Set Field

Set partials expose **Create Replicator Set Field** on selected text.

The command infers the blueprint and set from paths such as:

```text
resources/views/partials/sets/projects/_random_section.antlers.html
```

It then:

1. Finds the Replicator that owns that set
2. Replaces selected literal text with `{{ field_handle }}`
3. Appends the field to the matching blueprint set

It can add the first field to an empty set that has no `fields:` block yet.

It also upgrades inline empty maps like `fields: { }` into a normal `fields:` list before adding the first field.

## Field type prompts

Create Field and Create Replicator Set Field use type-specific prompts.

Examples:

- Text asks for input type
- Textarea adds the field without placeholder or character-limit prompts
- Markdown and Bard ask for button sets
- Assets asks for container and max files
- Toggle asks for default state
- Select asks for options and single or multiple values
- Link asks for allowed collections and asset container

Select options support flexible input.

| Input | YAML value |
| --- | --- |
| `blue` | `blue: Blue` |
| `option1,option2,option3` | each value gets a generated label |
| `bright red` | `bright_red: Bright Red` |
| `primary: Primary Color` | keeps the custom label |

## Stache cache refresh

After Set Blueprint changes an entry, or after blueprint and Replicator changes write files, the extension clears Statamic's Stache cache.

It runs:

```bash
php please stache:clear
```

when available, with a filesystem-cache fallback.

This helps the Control Panel see the new blueprint state instead of stale data.
